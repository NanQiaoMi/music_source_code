# 「温光浮字」手书 MV 动画精修与性能优化计划

> 日期：2026-10-20
> 范围：只改可视化效果 `cinematicLyricDrift` 及其手书渲染模块；不改效果 ID、设置字段、歌词/播放状态来源与 V7 核心视图。
> 背景：手写 MV 的结构与视觉方向已落地，但实际播放时动画偏粗糙、整体有卡顿；细节与镜头形式也偏单一。
> 本计划先解决"卡顿与粗糙"，再补"细节与形式多样性"，最后统一验收。

## 1. 现状诊断

### 1.1 卡顿（性能）假设

每一帧当前近似开销（1920×1080，dpr≤2）：

| 项目         | 每帧成本                                                           | 说明                                                       |
| ------------ | ------------------------------------------------------------------ | ---------------------------------------------------------- |
| 全屏渐变填充 | **约 12 次**                                                       | 阳光、光核、背光、横向光条、2 条窗光、暗角、四边压暗、颗粒 |
| 纸面纹理     | 1 次 `drawImage`（已缓存）                                         | 纹理尺寸约为视口 1.12 倍                                   |
| 内容层       | 涂鸦/插画逐帧重新 `roughen` + 线段描边                             | 大插画可产生数百段折线                                     |
| 文字层       | 每字 `save/translate/rotate/clip` + 2 次 `fillText` + `shadowBlur` | `shadowBlur` 在 Canvas2D 上非常昂贵                        |
| 换页         | 同时绘制进出两个镜头的全部内容                                     | 转场 0.35–1.1s 内帧耗时翻倍，体感就是"卡一下"              |
| 测量         | 页眉、页码、译文、余韵每帧 `measureText`                           | 小但可避免                                                 |
| 颗粒         | 每 150ms 换一张全屏 pattern                                        | 全屏合成 + 闪烁感                                          |

在 dpr=2 的全屏尺寸下，填充面积 ≈ 830 万像素 × 12 层，是卡顿的首要来源；`shadowBlur` 与逐帧路径重建是第二来源；转场双绘是第三来源。

### 1.2 粗糙（动画质量）问题

- **镜头**：纯正弦叠加的漂移有明显的循环/机械感；推镜在镜头末段减速到停，下一镜头重新启动，起停突兀。
- **书写**：逐字遮罩是线性/等速擦拭，中文单字被"扫"出来而不是"写"出来；字与字之间没有抬笔间隙，节奏平均。
- **涂鸦/描线**：所有笔画匀速生长，缺少起笔快、收笔慢的手感；线条在落笔期间没有"抖线"，完成后又过于僵硬。
- **标注**：下划线/圈画匀速出现，没有落笔压力与回弹。
- **转场**：所有 kind 都退化成同一种交叉溶解，缺少焦点拉动/暖光扫过/瞬间压暗的差异。
- **页眉/页码**：随镜头硬切出现，没有淡入淡出。
- **颗粒/光**：颗粒帧率低且幅度固定；光斑闪烁是正弦，像呼吸灯而不是环境光。

### 1.3 形式单一

- 版式基本集中在"锚点 + 居中主句"，长句一律折两行；竖排只支持单列短句。
- 每页涂鸦数量、位置、颜色组合相近；大幅插画每个 profile 只有一种。
- 页饰（胶带）位置固定，无邮戳、回形针、折角、红印章等变化。
- 转场、片尾、间奏都只有一种表现。

## 2. 目标与非目标

### 2.1 目标

1. 1920×1080、dpr=1 下效果绘制耗时中位数 **≤ 6 ms**，p95 **≤ 9 ms**；dpr=2 下中位数 **≤ 11 ms**、p95 **≤ 16 ms**（相对现有基线显著下降，具体以实测为准）。
2. 转场期间的帧耗时不超过稳态的 **1.5 倍**，不再出现可见掉帧。
3. 书写、涂鸦、标注、镜头、转场五类动画全部有独立的手感节奏，不再"匀速+交叉溶解"。
4. 版式、页饰、插画、转场、片尾至少各增加 1–2 种可识别变体，且全部由 seed 稳定决定。
5. 保持确定性：同一音乐时刻重绘/seek/暂停完全一致；`prefers-reduced-motion` 仍然静止且清晰。
6. 新增性能自适应降级：弱机自动降低光层/颗粒/双描边，不牺牲歌词可读性。

### 2.2 非目标

- 不引入 PixiJS/WebGL 或新依赖；继续使用 Canvas 2D。
- 不改 `VisualizationView`、播放器、全屏歌词等核心视图；不改设置字段与持久化。
- 不逐像素复刻任何参考 MV。
- 不在本轮做真实音频长时间播放验收（只做 harness + 真实应用冒烟，另留人工试听）。

## 3. 任务分解

### P0 性能（先做，减少后续迭代成本）

1. **静态屏幕层烘焙**：暗角 + 四边压暗 + 桌面边缘烘焙成一张屏幕空间缓存画布（key：尺寸 + 调色板 + 暗角强度），每帧只 `drawImage` 一次；设置变化时重建。
2. **光层半分辨率 + 限帧更新**：阳光、光核、横向光条、两条窗光、背光渐变画到 `w/2 × h/2` 的离屏画布，最多每 80–100 ms 重画一次；每帧用 `screen`/`multiply` 各贴一次。光源慢速漂移足够，肉眼无差别。
3. **移除文字 `shadowBlur`**：改为"低透明度暖色重描 + 1px 偏移"的廉价字缘光，或在书写中的字后叠一枚缓存的径向光斑精灵。
4. **笔触路径缓存**：`handwrittenDoodles` / 插画按 spec 对象缓存 roughen 后的点列与 `Path2D`；绘制完成后直接用缓存路径一次描边，避免逐帧重建与 GC。落笔中的动画仍按进度裁剪，但复用缓存点列。
5. **文本布局缓存**：页眉、页码、译文、间奏余韵、片尾署名按（文本+字号+字体+行宽）缓存字形数组与测量结果；`measureText` 只在缓存未命中时调用。
6. **转场快照**：转场开始时把 outgoing 内容层（不含纸/光）抓进一张离屏画布，转场期间只绘制"纸 + 快照淡出 + incoming 内容淡入"，避免每帧双绘。
7. **转场/颗粒节流与合成**：颗粒更新降到 12fps 且改为单层低透明度；光层与内容层使用 `globalAlpha` 一次性合成。
8. **自适应画质**：效果内部用 EMA 统计每帧绘制耗时；>12ms 进入 tier1（跳过干笔重影、降低灰尘与颗粒、光层 5fps），>18ms 进入 tier2（停用大幅插画、涂鸦改缓存静态、光层 3fps），<8ms 且持续 2s 回到上一级；带滞回，避免抖动。
9. **降低每帧分配**：把热路径里的数组/闭包（glyph 数组、渐变、临时对象）尽可能复用或缓存；`resolveHandwrittenScene` 已在镜头级缓存，满足。

### P1 动画手感

1. **镜头噪声化**：用 2–3 octave 的平滑 value noise 替代正弦叠加；镜头内持续缓慢漂移，不再末段停死；镜头入场 0.5s ease-out、出场 0.4s ease-in；纸张与文字分层视差（文字 1.0×、纸 0.85×、插画 1.08×）。
2. **书写节奏**：按单元确定性加入 25–60ms 抬笔间隙；单字遮罩改为斜向湿润边缘 + 软边（两遍不同 alpha 的裁剪），收笔时出现墨滴；写完 120–180ms 内做一次轻微沉降（scale 1.012→1、墨色变实）。
3. **涂鸦手感**：每笔 `easeOutCubic` 生长、笔与笔之间 30–80ms 延迟；落笔期间 10fps 时间量化抖线（boiling line），完成后静止；胶带/邮戳用轻微回弹。
4. **标注手感**：下划线两笔错时、宽度有压力变化；圈画用 easeOutBack 收口；荧光笔从左到右 `easeInOut` 并留笔触端头。
5. **三种转场**：`focus-pull`（outgoing 轻微放大 + 淡出，incoming 淡入并在 120ms 内清晰）、`flare-cut`（暖光扫过 + 极短曝光抬升 4%）、`lights-out`（短暂压暗到 12% 后淡入，不闪黑）。通过快照实现，帧耗时稳定。
6. **页眉/页码**：每镜头淡入 400ms、切页前 500ms 淡出；页码换页时交叉淡化。
7. **光与颗粒**：去掉正弦闪烁，改为 20–60s 周期的慢漂移 + 极轻的灰尘扰动；颗粒 12fps、透明度随调色板与设置变化；暗角与纸边保持稳定。
8. **减弱动态**：以上全部关闭，只保留静态纸面 + 清晰歌词 + 即时切换。

### P2 细节与形式多样性

1. **版式变体**（按 seed 稳定选择）：
   - 居中 / 左三分 / 右三分 / 偏低 / 偏高 / 阶梯错落 / 斜向递进；
   - 竖排单列 / 竖排双列（长句自动分列）；
   - 单个大字（1–2 字主句时放大约 1.6×）；
   - 页边批注式（主句缩小靠边，页眉位置写一行小字）；
   - 明信片式（文字落在下三分之一，上半页留给大插画与页饰）。
2. **页饰变体**：胶带位置/角度/长度按镜头变化；新增邮戳、回形针、折角、撕纸片、小号红印章（部分歌词页）；页码偶尔写成手写分数或带小圆圈。
3. **涂鸦扩展**：新增纸张、邮戳、纸飞机、咖啡渍、雨、山、收音机、磁带、星群、缎带、书名号括号等 10 种左右，按 profile 分池、同镜头不重复。
4. **插画扩展**：每个 profile 至少 2 种大幅线稿，seed 选取；间奏在"余韵"与"器乐速写"之间交替。
5. **片尾变体**：手写署名 + 印章（现有）、明信片式（横排文字 + 邮票 + 邮戳）、竖排落款式；按歌曲 seed 与片尾长度选择。
6. **墨色与强调变化**：主句墨色在 3 档墨密度中稳定选择；重点标注在暖金/朱红两色间选择；个别镜头主句用 accent 色下划线。
7. **镜头形式**：每 2–3 句更换构图重心；重复句、副歌连续句可放大为主视觉；间奏与尾声使用不同装饰语言。

### P3 验收与清理

1. 性能：用临时 harness 在 1920×1080 dpr1/dpr2、2560×1080、390×844 下测 6s，输出中位数/p95/掉帧率；对比基线写入 `scratch/perf/AFTER.json`。
2. 稳定性：转场前后、暂停/seek、歌词未加载、无歌曲、间奏、片尾各截图；无 Canvas 异常、无黑帧、无布局溢出。
3. 确定性：`?t=30` 与 `setTime(30)` 像素差 < 0.5%；暂停冻结。
4. 代码：`vitest`（新增/既有）、`tsc --noEmit`、ESLint 改动文件全绿；临时 harness 删除。
5. 文档：更新设计规格中的动画/性能章节，记录实测数字与降级门限。

## 4. 验收标准

- 6 个镜头连续播放（含 2 次转场、1 次间奏、1 次竖排、1 次片尾）目视无明显掉帧；harness 数据达标。
- 书写不再像"扫描线"：单字可见斜向湿润笔尖，字间有抬笔节奏。
- 涂鸦、标注、转场至少三种节奏差异可辨识；版式与页饰肉眼可看出镜头间变化。
- 弱机降级时歌词仍然清晰、可读，且不影响暂停/seek 确定性。

### 5.2 P1 动画手感

已实现：value noise 双层镜头漂移 + 内容 1.16× 视差；字间确定性抬笔间隙；写完 0.2s 沉降；
笔尖湿墨/飞溅仅在书写字上；涂鸦 easeOutCubic + 笔间错峰 + 100ms boiling line（时钟由音乐时间派生）；
标注 easeOutBack 回弹；荧光笔改为整道带起伏的水彩带；页眉/页码淡入淡出；
三种转场（focus-pull / flare-cut / lights-out）有不同处理；颗粒/光改为慢漂移。
铅笔辅助稿降到 0.055（active）/0.28（future），避免未写到的字像"幽灵重影"。

### 5.3 P2 细节与形式

已实现：

- 版式变体 9 种：center / left / right / low / high / stagger / diagonal / postcard / margin，按 seed 稳定选择；
- 新增 11 种涂鸦（postageStamp、paperplane、coffeeRing、rain、mountain、radio、cassette、starCluster、ribbon、bracket、quote）；
- 每 profile 2 种大幅线稿（window 补充窗帘/窗台盆栽/斜射光，stamp 补充齿孔/风景/面值）；
- 页饰 5 种：胶带（位置/角度/数量变化）、回形针、邮票、折角、小号红印章（label 按 seed 选）；
- 片尾 3 种变体（署名 / 明信片 / 竖排落款），竖排落款已修正艺人/专辑/印章与标题的成组关系；
- 重点标注暖金/朱红两色；墨色密度 3 档；竖排短句单列（**未做竖排双列**，见 5.5）。

### 5.4 实测数据

测量环境：冻结 worktree（3031，commit c73a872 + 各阶段效果文件），headless Chrome 155，
pinned 暂停路径，400 帧滚动窗口；draw = 单次 `drawCinematicLyricDrift` 的 JS 提交耗时。

| case              | draw med base→after | draw p95  | frame med | dropped |
| ----------------- | ------------------- | --------- | --------- | ------- |
| 1920×1080 dpr1    | 1.30→1.30 ms        | 1.70→1.70 | 6.10      | 0/400   |
| 1920×1080 dpr2    | 1.30→1.30 ms        | 1.60→1.90 | 6.10      | 0/400   |
| 2560×1080 dpr1    | 1.30→1.30 ms        | 1.60→1.90 | 6.10      | 0/400   |
| 390×844 dpr2      | 1.20→1.20 ms        | 1.60→1.60 | 6.10      | 0/400   |

| 1080p t=60 转场   | 1.30→1.20 ms        | 1.60→1.70 | 6.10      | 0/400   |

结论：JS 提交耗时本来就低，真正卡顿在光栅/过绘制 → 用压力场景验证：

- **1920×1080 @dpr4（7680×4320 backing）**：优化前 ad-hoc p95 36.3ms / max 290ms / 15 丢帧；
  优化后 frame med 6.1ms、p95 6.2ms、max 6.7ms、**0/400 丢帧**（4K 级自动进入 2 档）。
- **bundled Chromium（软件光栅）1080p dpr1**：优化前 12–18fps → 优化后 ~15fps（同协议下 33→66ms 波动较大，
  受软件光栅与机器负载影响，仅作方向性参考）。

### 5.5 确定性与视觉验收

- 确定性脚本（`scratch/perf/_lead_determinism.py`）在 t=30 / 60 / 219 各抓 2–3 次（含不同 settle）：
  像素差 >8 的像素占比 **0.000%**，平均绝对差 0.02–0.03/255；字节哈希差异仅来自 GPU 光栅的
  1–2 级像素抖动与 PNG 编码，可认定「同一音乐时刻同一帧」。
- 视觉抽查：t=1.5（片头）、30（竖排）、47.6/60.2（转场）、100/130（横排/斜向）、112（间奏余韵）、
  218/236（片尾）、移动端 390×844、超宽 2560×1080，无 Canvas 异常、无黑帧、无裁切。
- 未做/留待后续：竖排双列（长句分列）、页边批注小字版式、撕纸片页饰、页码手写分数；
  这些属于「形式再加一种」的增量，不影响本轮验收。
