## State fixture (Player / lyrics only)

The Player surface needs a `currentSong` to render representative content. The script seeds the
real Zustand persist envelopes (not a new storage format):

```json
{
  "ui-store-v2": {
    "state": {
      "currentView": "player",
      "themeMode": "dark",
      "themeColors": {
        "primary": "rgb(55, 65, 81)",
        "secondary": "rgb(31, 41, 55)",
        "accent": "rgb(75, 85, 99)",
        "complementary": "rgb(30, 41, 59)",
        "background": "rgb(8, 9, 12)",
        "surface": "rgb(15, 17, 23)",
        "gradient": ["rgb(55, 65, 81)", "rgb(31, 41, 55)", "rgb(75, 85, 99)"],
        "text": "rgb(255, 255, 255)",
        "textMuted": "rgba(255, 255, 255, 0.6)"
      },
      "isDynamicTheme": false
    },
    "version": 2
  },
  "player-store": {
    "state": {
      "currentSong": {
        "id": "s3-2-fixture-daoxiang",
        "title": "稻香",
        "artist": "周杰伦",
        "album": "魔杰座",
        "cover": "https://images.unsplash.com/photo-1459749411175-04bf5292ceea?w=600&h=600&fit=crop",
        "audioUrl": "data:audio/wav;base64,...(0.1s silent WAV)...",
        "duration": 223,
        "source": "local",
        "lyrics": "<LRC fixture>"
      },
      "volume": 0.7,
      "isMuted": false,
      "playbackRate": 1,
      "loopMode": "none"
    },
    "version": 0
  }
}
```

Rationale:

- `ui-store-v2` is the app's only view/theme persist key; the payload key/version/shape match
  `src/store/uiStore.ts` (`partialize` = currentView/themeMode/themeColors/isDynamicTheme, v2).
- The current-song fixture uses the built-in demo track metadata and the LRC fixture copied from
  `src/services/lyricsSearchService.ts` (稻香-周杰伦).
- `source:"local"` + a tiny inline silent WAV prevents `MultiSourceResolver` from substituting a
  remote stream for the synthetic song id; without it the app would surface its inline
  "audio unavailable" panel and pollute the protected view. The capture is paused (no playback),
  so audio is not actually heard.
- The Next.js dev indicator (`nextjs-portal`) is hidden with CSS only; application DOM/classes are
  untouched. All screenshots are taken with `animations:"disabled"` to freeze transient motion.

The two recorded console errors per Player/lyrics view are pre-existing dev-mode network 401s from
external demo/API requests, not uncaught exceptions (`pageerror` = 0). Home had 0 console errors.

## Reproduce

From this worktree (dev server must run from this worktree, not the main repo):

```powershell
# 1. Start a dev server on an unused port
node node_modules/next/dist/bin/next dev --webpack -p 3037

# 2. In another shell, wait for readiness
curl.exe -s -o NUL -w "%{http_code}" http://127.0.0.1:3037   # 200

# 3. Playwright is not a committed dependency; install it without touching package.json/lock
npm install --no-save --legacy-peer-deps playwright@1.64.1

# 4. Capture (default output = this directory)
npm run perf:screenshots:s3-2

# Equivalent explicit form:
node scripts/perf/capture-s3-2-screenshots.mjs \
  --base-url http://127.0.0.1:3037 \
  --out docs/nbl/plans/2026-10-21-arch-perf-execution/evidence/screenshots/s3-2
```

The script uses Chrome via `channel:"chrome"` and
`executablePath:"C:/Program Files/Google/Chrome/Application/chrome.exe"`; it does not download
Chromium. Override with `--chrome-path` or `CHROME_PATH` if Chrome lives elsewhere. `--out` and
`--base-url` make the output directory and server configurable.
