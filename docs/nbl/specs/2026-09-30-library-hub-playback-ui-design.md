# 管理中枢视觉统一与连续播放设计方案

- 日期：2026-09-30
- 状态：书面规格已由用户确认，实施及集成验证中
- 分支：fix/library-hub-playback-ui
- 范围：音源管理弹窗、资料库资产管理中枢、管理页播放栏与页面导航

## 1. 目标

统一“全网多音源矩阵与扩展中心”和“资料库资产管理中枢”的视觉与交互层次，使其延续主页面的深色玻璃拟态、青蓝强调色、柔和渐变和圆角材质；修复从主页面进入资料库时整页重载、导致当前音频会话被销毁的问题；让管理页的播放控件不遮挡搜索和资产内容。

本轮基于现有结构做定向改进。音源管理已拆分为五个 Tab，资料库已使用 SettingSection / SettingRow 和现有图表组件，不重复重构这些边界，也不修改 Home View、Player View 或全屏歌词核心视图。

## 2. 现状与代码证据

### 2.1 连续播放问题

- 主页面工具栏入口在 src/components/layout/HeaderToolbar.tsx 使用普通 href="/data-manager"。
- 导航岛的“音乐库管理器”入口在 src/components/layout/AppleUnifiedNavIsland.tsx 通过 window.location.href 跳转。
- 两种入口都会触发整页导航。根布局中的 GlobalClientComponents 虽然调用 useAudioPlayer 并渲染 FloatingPlayer，但整页卸载仍会销毁 HTMLAudioElement 和其当前流。
- src/hooks/useAudioPlayer.ts 使用模块级 Audio 单例；src/app/layout.tsx 将 GlobalClientComponents 放在路由页面内容之外，适合通过 App Router 客户端导航保留同一媒体会话。
- player-store 与 audio-store-v4 持久化歌曲和进度等部分状态，但不持久化 isPlaying；因此不应通过自动重播来掩盖整页刷新造成的会话丢失。

### 2.2 页面视觉差异

- src/components/library/UnifiedDataManagerHub.tsx 的总览页使用 max-w-7xl，聚搜、云端曲库和离线下载使用 max-w-[1720px]，导致同一中枢内的内容宽度不一致。
- src/components/player/FloatingPlayer.tsx 默认位置为左侧中段（left: 28, top: 280），会覆盖聚搜页搜索栏的左侧区域。
- src/components/sources/SourceManagementModal.tsx 保持为五个 Tab 的弹窗，最大宽度为 max-w-4xl；其内容已复用设置分组和状态组件。
- DESIGN.md 已规定玻璃卡片、深色背景和高饱和强调色；本轮沿用现有 Tailwind、Framer Motion、Zustand 与 Glass 组件，不增加依赖。

### 2.3 访谈状态

用户已确认书面规格与实施方案：采用深色玻璃拟态和青蓝渐变；在客户端路由下保留播放会话、当前进度和队列；播放前暂停状态保持暂停；加载或失败时不自动重开或跳歌；管理页使用底部紧凑播放栏并为内容留白；资料库按统一页面壳适配桌面与笔记本。实现中发现的队列状态分叉也纳入修复：播放栏显示的 QueueStore 队列必须与上一首/下一首实际操作一致，重复歌曲需要尊重当前索引。

## 3. 方案比较与选型

| 方案                                | 做法                                                                                            | 取舍                                                                                       |
| ----------------------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| A. 客户端导航与管理页播放坞（采用） | 保留独立资料库路由；用 Next.js 客户端导航进入；只在管理页显示底部紧凑播放栏，并为内容留出空间。 | 直接消除已确认的整页重载路径；沿用全局音频单例和既有状态；不改变持久化格式。               |
| B. 整页刷新后恢复播放               | 刷新后根据持久化歌曲和时间重新解析音源并自动续播。                                              | 需要恢复流地址和队列，可能使用过期链接；受浏览器自动播放限制；与“不自动重开失败曲目”冲突。 |
| C. 将资料库改为主页面覆盖层         | 取消独立路由，以弹层或面板承载所有资料库分区。                                                  | 改动范围更大，需要重新处理主页面布局、面板生命周期和导航语义。                             |

选择方案 A。该方案只保证应用内部客户端路由切换时保持播放会话；手动刷新或直接打开新会话仍遵循现有规则，不自动续播。

## 4. 设计与交互方案

### 4.1 页面导航与音频所有权

- HeaderToolbar 的资料库入口改为 Next.js 客户端导航链接；AppleUnifiedNavIsland 的入口使用 App Router 的客户端跳转。
- 页面切换期间保留 RootLayout 下的 GlobalClientComponents 和既有 Audio 单例，不创建第二个 HTMLAudioElement，不因进入资料库而调用 play、load、seek 或修改当前曲目。
- 页面返回路径继续使用现有客户端路由。
- 不修改 audio-store-v4、player-store、队列或 IndexedDB/localStorage 数据结构。

### 4.2 管理页底部紧凑播放栏

- 主页继续使用现有可拖动 FloatingPlayer。
- 路径为 /data-manager 时，显示一条底部紧凑播放栏，提供当前曲目、播放/暂停、上一首/下一首、进度与队列入口；全部订阅现有播放与队列状态。队列入口在该路由实际挂载并打开现有 QueuePanel，关闭后复位共享面板状态。
- 管理页滚动区域为播放栏和安全边距预留空间；播放栏在 1024px 左右窗口宽度下仍可操作，不遮挡搜索框、列表末行和主要按钮。
- 播放栏从 QueueStore 读取队列与 currentIndex；用户明确点击上一首或下一首时，先按当前播放歌曲 ID 校准队列索引，保持显示、队列面板和实际切歌一致，并沿用现有循环/随机模式。若正在播放的曲目已从队列移除，下一首播放 currentIndex 指向的候选，上一首播放该候选的前一项；空队列不切歌，单候选仍可播放。队列包含重复歌曲 ID 时按 currentIndex 确认当前项；队列面板单行删除只移除所选索引，不删除其它同 ID 项。
- 进入前正在播放时，歌曲和进度自然延续；进入前暂停时仍暂停；加载或失败时保留当前状态并显示现有错误，不自动重试、不自动切歌。
- 从播放栏执行明确的播放/切歌操作仍交给现有播放器逻辑处理。

### 4.3 统一视觉语言与页面布局

- 统一资料库七个分区的页面壳、导航状态、卡片、按钮、间距和最大内容宽度；宽度使用 max-width 1720px 并随视口缩小，两侧留白使用响应式间距。
- 复用 SettingSection、SettingRow、StatusDot、GlassCard 等现有组件。以深碳色和轻透明玻璃作为底层，以青色/蓝色作为主要交互强调；紫色只作辅助，不把所有卡片做成同一灰阶。
- 全景看板突出存储用量和配额，之后按音质、云端账号、曲库健康分组；保留现有图表与统计口径。
- 聚搜保留既有关键词、平台、歌曲/歌单模式、质量筛选、热门关键词和批量操作；明确显示搜索结果、未登录锁定、空结果、加载和错误状态，未登录时给出可直接打开账号登录的入口。
- 搜索采用请求序号保护；关键词、来源或模式变化、清空、锁定、缓存命中或组件卸载后，之前启动的异步请求不得改写当前结果、错误或加载态，也不得在重新挂载后覆盖共享搜索结果。
- 音源管理继续保持弹窗和原五个 Tab；统一标题、导航选中态、状态摘要、表单层级、折叠详情、圆角与边框，不改音源配置和登录行为。
- 遵循系统减少动态效果偏好：音源弹窗的进入/退出位移和缩放、矩阵及脚本开关布局动画，以及弹窗范围内 CSS 转场/循环动画按偏好降为静态或近乎即时；主页和播放视图不受此弹窗作用域规则影响。
- 其余五个资料库分区保留现有数据操作和组件，仅统一页面表面、响应式导航和状态层级。

### 4.4 响应式与无障碍

- 1024px 及以上窗口完整显示主要操作；窄于顶部完整导航的窗口沿用横向可滚动导航，内容单列堆叠，表单控件保留可点击宽度。
- 所有主内容卡片允许收缩（min-width: 0），避免中文标题竖排和横向页面溢出。
- 图标按钮保留可访问名称，键盘焦点清楚；动画遵循 reduced-motion 偏好，避免影响音频播放和进度操作。

## 5. 关键状态与边界

| 场景                                  | 预期行为                                                                 |
| ------------------------------------- | ------------------------------------------------------------------------ |
| 页面进入前正在播放                    | 客户端导航不卸载媒体元素；歌曲与进度连续。                               |
| Zustand 水合恢复非默认管理分区        | 首次加载即挂载恢复出的分区；工作区不能因 Keep-Alive 初始集合过期而空白。 |
| 页面进入前已暂停                      | 继续保持暂停；导航不触发自动播放。                                       |
| 音频加载中                            | 管理页播放栏显示加载状态；不重新 load 或切歌。                           |
| 当前曲目失败                          | 保留错误反馈；不因路由切换自动重试或跳过。                               |
| 当前没有歌曲                          | 不显示占位播放栏，管理内容可正常使用。                                   |
| 当前曲目仍在队列但两个 store 索引不同 | 按歌曲 ID 对齐后切歌，避免跳过可见队列中的下一首。                       |
| 当前曲目已从队列移除                  | 下一首选择 currentIndex 候选，上一首选择其前一项；单候选仍可切换。       |
| 管理页点击队列入口或关闭队列          | 打开复用的 QueuePanel；关闭后 panels.queue 复位。                        |
| 用户未登录                            | 聚搜显示锁定原因与账号登录入口；不伪装为“无搜索结果”。                   |
| 搜索无结果或请求失败                  | 分开呈现无结果与错误，提供重试或修改关键词入口。                         |
| 新搜索启动后旧请求才返回              | 旧请求不得覆盖新结果/错误，也不得提前清除新请求 loading。                |
| 聚搜组件卸载后旧请求才返回            | 已卸载组件的请求不得写共享 store 或覆盖重新进入后的搜索结果。            |
| 队列包含相同歌曲 ID                   | 只高亮 currentIndex 对应条目；移除单条只删除被操作的队列索引。           |
| 空曲库、存储高占用、离线任务运行      | 保留现有统计与任务行为，视觉状态仍可辨认。                               |
| 1024px 笔记本宽度                     | 导航可达、内容无横向溢出、播放栏不压住操作。                             |

## 6. 范围边界

- 不修改 Home View、Player View、全屏歌词核心视图。
- 不改变音源解析策略、账号认证、搜索 API 路由/请求参数/成功响应 schema、下载/导入/歌单等业务行为。内部搜索聚合只补充失败信号：有可尝试来源且全部请求失败时抛出可捕获错误；至少一个来源成功响应（即使结果为空）时保留正常结果；无可尝试来源及自定义脚本成功返回空数组时仍视为空结果。歌单搜索路由对“尝试过来源且全部失败”返回非成功 HTTP 状态（503），让界面进入错误/重试状态；部分成功空结果和无来源可尝试仍维持成功空响应。
- 不引入新的 UI/状态/音频依赖。
- 不变更 localStorage、IndexedDB、Zustand persist 或数据库格式。
- 不实现整页刷新后的自动续播；自动恢复失败曲目也不在本轮范围内。
- 不删除暂时未使用的组件或字段，除非实现过程中证实其与本方案直接冲突。

## 7. 验收标准

1. 从 HeaderToolbar 和 AppleUnifiedNavIsland 两个入口进入 /data-manager 均使用客户端导航，当前音频会话不被销毁。
2. 播放中、暂停中、加载中和失败状态符合第 5 节定义；管理页播放栏显示的队列与上一首/下一首执行的队列一致，当前歌曲 ID 会校准两个 store 的索引，已移出队列时采用明确候选语义；重复 ID 只高亮实际当前索引且单行移除只删一项；队列入口可实际打开并关闭 QueuePanel，进度数据来自现有播放状态。
3. 主页的可拖动播放器样式与行为保持不变；资料库页使用底部播放栏，内容可滚动到末尾且不被遮挡。
4. 资料库七个分区共用 max-width 1720px 的内容体系；总览与聚搜在 1024px、1280px、1440px 和 1780px 视口下保持可用、无页面横向溢出。
5. 音源管理五个 Tab 的切换、展开配置、登录和诊断行为保持；视觉状态与资料库玻璃语言一致，并遵循系统减少动态效果偏好。
6. 聚搜能区分锁定、空结果、加载与错误，并提供符合状态的下一步操作；来源全失败显示可重试错误，成功空结果仍显示空结果，迟到请求不得覆盖新搜索状态，卸载的请求不得写共享结果 store。
7. 类型检查、相关组件/导航测试、生产构建和浏览器视觉检查通过；若遇到已存在基线问题，记录具体命令、文件和影响范围。
