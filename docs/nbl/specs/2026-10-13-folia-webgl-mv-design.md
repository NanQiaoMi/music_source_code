# 「温光浮字」Folia 式 WebGL 歌词 MV 重做规格

> 状态：待用户复核。用户已确认“整套 WebGL MV”；代码实施须等本规格复核通过。
>
> 目标：让「温光浮字」成为由歌词、镜头、光场和空间共同编排的完整歌词 MV，而不是在背景上叠加卡拉 OK 字幕。
>
> 参考范围：只读克隆位于 D:\26project\folia-major-study，HEAD 为 9a01e78。以 2026-10-13 可见的绘光、云阶和浮名实现为机制参考。本项目独立实现，不复制 Folia 源码、素材、字体或片段。

## 1. 从截图和 Folia 得出的设计结论

当前截图中的固定透视地网格、顶部灯轨、三束平面渐变光和居中双行歌词，让画面像一张通用舞台底图。歌词虽有逐字变亮，却没有融入场景空间；页眉、两组播放器控件、AI 文案与角色又同时争夺注意力。这是渲染结构和全屏呈现的问题，继续调色或增加粒子不能消除。

Folia 的差异来自三种机制：

| 参考         | 学习的机制                                                               | 在「温光浮字」中的用途                                                 |
| ------------ | ------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| 云阶 Partita | 歌词行错落排布、逐行推进、字组在稳定版式中连续点亮                       | 让副歌词形成有节奏的阶梯和层次，不再固定贴在主句上下                   |
| 浮名 Fume    | 一句歌词可成为超大主视觉，前后歌词作为远景；镜头沿文字场平稳游移         | 在少数重点镜头里让文字越过中心或贴近画面边缘，建立 MV 海报式构图与景深 |
| 绘光 Lumiere | WebGL 场景图层、体积光场、雾、线稿、尘点、文字 Bloom、光束照字与逐字窗口 | 作为统一的空间与光线系统，使每个字属于镜头中的光场                     |

以上是构图和渲染机制，不是三种可切换模式。整首歌共享同一套配色、材质、粒子尺度和转场语言；每个镜头只改变歌词构图重心、光位和镜头方向。参考 [Partita 实现](https://github.com/chthollyphile/folia-major/blob/9a01e788ed52d25ea01b1f0d37934e5e371ae82b/src/components/visualizer/partita/VisualizerPartita.tsx)、[Fume 全曲排版](https://github.com/chthollyphile/folia-major/blob/9a01e788ed52d25ea01b1f0d37934e5e371ae82b/src/components/visualizer/fume/fumeArticleLayout.ts)、[Lumiere 场景层](https://github.com/chthollyphile/folia-major/blob/9a01e788ed52d25ea01b1f0d37934e5e371ae82b/src/components/visualizer/lumiere/scene.ts) 与 [Lumiere 字幕窗口](https://github.com/chthollyphile/folia-major/blob/9a01e788ed52d25ea01b1f0d37934e5e371ae82b/src/components/visualizer/lumiere/text/lyricWindow.ts)。

## 2. 总体设计

把当前同一 Canvas 2D 回调中的舞台和字幕，改为此效果专属的全屏 PixiJS WebGL 场景。独立的歌词 MV 编排器按绝对音乐时间选取镜头、版式、灯位、字形状态和转场；Pixi 场景负责多层 GPU 合成。歌词字形、线稿与光场必须能互相遮挡、响应照度并拥有不同景深。

采用 PixiJS 8 并只在选择此效果时懒加载。它适合全屏 2D 场景树、分层滤镜和纹理文字；Folia 绘光也采用 Pixi/WebGL。现有 Three.js 依赖保留给已有 3D 系统，V8 的 RenderEngineManager 不作为此次入口：当前正式可视化页仍直接调度 Canvas 效果，V8 视图没有接管该页面。此次新增独立 Pixi 运行时，不迁移其它效果。

## 3. 视觉构图与镜头语言

### 3.1 统一的视觉语法

- 全画幅建立有色温变化的环境光场：深蓝、青绿、紫灰或暖金由现有主题色派生；禁止整屏近黑后只留几根线。
- 移除截图式固定顶部灯架、三盏均匀灯、地面透视网格和中心舞台地平线。每首歌只生成少量彼此有关的抽象线稿、形状和光源位置，避免把通用“演出舞台”当作背景。
- 主歌词是每个镜头的构图主体，但不锁在屏幕正中心。镜头可选择左/右三分位、偏上/偏下、错落阶梯、窄竖列或大字靠边裁切；锚点由内容宽度和安全区约束，避免随机抖位。
- 主句保持清晰可读并随视口缩放；邻句最多两句，缩小到主句的 0.46–0.64 倍，置于不同深度和不对称位置，透明度仍足以辨认。唱过的歌词逐渐进入远景，不整首累积成文字墙。
- 普通歌词镜头以一条主句为主；重复句、已有副歌标记或内容较短且连续的歌词可以成为重点镜头，放大到约 0.72–0.88 倍画宽。只有重点镜头使用 Fume 式贴边裁切或强推镜，常规句子不强行超大。
- 云阶式错落和浮名式远近文字作为镜头编排变体，保留可读安全距离；中文竖排只在短中文/日文文本且宽高比合适时使用，不把拉丁文本拆成竖列。
- 灯束经过歌词时，当前字/词的亮度和光晕有局部响应；光束被前景线稿或浮尘遮住时也保留空间顺序。不能只在字上叠一圈同样亮的阴影。

### 3.2 歌曲镜头编排

编排器读取现有歌曲身份、播放时长、歌词行开始/结束时间和可用翻译。根据行间空档、连续行数量、重复歌词及歌词密度生成全曲时间线。没有主歌/副歌标签时只称为“重点段/普通段”，不宣称准确理解歌曲语义。镜头配置用歌曲身份和行序号稳定派生；播放、暂停、seek、回退和重绘都从绝对音乐时间重建相同结果。

| 段落              | 画面安排                                                                                                                |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 前奏              | 先给环境光、线稿和远景建立空间；首句进入前不显示伪歌词。曲名/艺人最多作为短暂片头署名，不拆成歌词字形。                 |
| 普通歌词          | 1 句主视觉，最多 2 句退后陪衬；字形、光束和镜头小幅移动，约每 1–2 句更换构图锚点。                                      |
| 重点段            | 主句放大或错列，背景图形和光场变丰富；改变光位和景深，不用整屏频闪。                                                    |
| 间奏/长空档       | 歌词退出；保留独立器乐镜头，用主题线稿、缓慢焦散、雾和浮尘继续演出。                                                    |
| 尾声              | 末句结束后先保留器乐画面；仅最后约 6–8 秒进入片尾署名，曲名先显、艺人随后显，不把元数据误当歌词。短尾声按剩余时长压缩。 |
| 无歌词/歌词未加载 | 只播环境光和图形的无字镜头；未选歌曲时为空场的低幅呼吸，不拆曲名造词。                                                  |

## 4. WebGL 场景与合成层

图层之间允许文字、雾、线稿和光束产生遮挡与不同景深，不再把全部元素绘制成同一平面。

| 顺序 | 图层         | 表现与约束                                                                       |
| ---- | ------------ | -------------------------------------------------------------------------------- |
| 1    | 环境暗场     | 有主题色的深色渐变、暗角和轻微光斑；连续环境，不是一整片纯黑遮罩。               |
| 2    | 光场与雾     | 低频 GLSL 着色器形成体积光、烟雾、光晕和缓慢焦散；镜头切换时连续变形。           |
| 3    | 远景图形     | 稀疏星点、歌词残影和低对比线稿/主题符号；轮廓随镜头切换交叉淡入淡出。            |
| 4    | 中景         | 少量主题化几何物、层叠形状或文字碎片；只呼应歌词，不使用固定舞台结构。           |
| 5    | 歌词发光底层 | 逐字光晕、短径迹、重点词十字闪光；只对当前/刚结束字组短暂出现，限制 Bloom 范围。 |
| 6    | 歌词主层     | 当前主句与前后歌词窗口；按镜头位置排版，具有不同字号、深度、遮罩和亮度。         |
| 7    | 前景         | 少量失焦微尘/散景缓慢掠过；不能遮挡主句阅读区域。                                |
| 8    | HTML 控件层  | 模式、设置、录制和唯一一组播放控件；短暂停留后淡出，交互/键盘焦点恢复。          |

## 5. 歌词时序和动画规格

### 5.1 字词点亮

- 沿用已选同步策略：当前歌曲只有 LRC 行时间时，按可读字素/短词组权重对行区间做确定性进度估算；明确这是视觉估算，不声称是真实逐词时间。若现有歌词对象已提供可用词级时间，可直接优先使用，不新增持久化格式。
- 当前字/词以连续软遮罩扫光显影，避免整行只有一个孤立亮字突然闪烁。中文按字素组推进，英文尽量按词组推进；标点跟随相邻单位，不单独发光。
- 当前字组偏暖白/主题主色，未唱文本为冷灰主题色，已唱文本短暂留低亮余辉后退入远景。字光由所在位置的舞台光场调制，不能全行同强度金色填充。
- 主句入场约 300–480 ms；点亮沿真实/估算时间连续推进；末字结束后停留约 250–450 ms，再于 450–700 ms 内淡出或进入下一镜头。时序从音乐时间计算，不从渲染帧数累积。
- 翻译仅在现有译文行与主歌词行时间近邻对齐时显示，位置避开主句安全区、亮度低于主歌词；无匹配译文时不显示。

### 5.2 运镜、转场与声音响应

- 镜头以缓慢推近、拉远或横移为主；每镜头最多约 3–5% 视野变化，起止缓入缓出，不持续绕场或匀速漂移。
- 同类光位在约 0.6–1.0 秒内交叉渐变；段落大切换约 0.8–1.2 秒，最多使用一次轻微散焦/曝光过渡，不闪黑、不硬切。相邻镜头避免重复同一方向运动。
- 强拍可增强灯束、字光和少数微粒；无节拍分析证据时不伪造精准踩点。音频响度/频段只小幅调制照度、雾密度和微粒，不导致整屏闪动。
- 暂停时歌词、镜头和转场固定在当前音乐时刻；环境尘雾以低幅度呼吸。恢复、倍速、seek、回退、切歌和歌词迟到均从当前绝对时间重算。
- prefers-reduced-motion 下关闭持续运镜、粒子漂移和强度脉冲；保留静态光场、清晰歌词、seek 与即时镜头变更。

## 6. 全屏控件和干扰收敛

- 此效果进入全屏后，保留一个主播放条、播放/切歌、进度拖动和退出全屏入口。当前截图中的重复小播放器、AI 语录和角色装饰不作为歌词 MV 的画面元素；全屏歌词舞台不显示这些非必要浮层。
- 鼠标、键盘或触屏活动后立即恢复控件；约 2.2 秒无操作后，页眉、底部控制条和设置入口以 250–350 ms 淡出。隐藏时设置不可点击；键盘焦点不因自动淡出而丢失。
- 单击/轻触无控件背景仅显示控件，不触发播放/暂停或 seek；再次操作可使用控件。键盘快捷键沿用现有绑定，Escape/全屏退出行为不变。
- 本次改动只作用于「温光浮字」全屏沉浸态，不重新设计 Home、Player 或其他可视化效果。

## 7. 实现边界与故障处理

- 保留效果 ID cinematicLyricDrift、名称「温光浮字」、现有设置字段和用户已保存的数据；保留当前歌词/播放状态来源和持久化格式。
- Pixi 运行时由独立客户端组件懒加载；不在 Next.js 服务端创建 WebGL 资源。尺寸由 ResizeObserver 更新，字体/纹理按主题与视口缓存，更新布局时清理旧缓存。
- 运行时只缓存当前镜头及相邻镜头；字形、粒子、滤镜和离屏纹理有上限。动画循环在页面隐藏时暂停；释放 renderer、texture、filter、observer、RAF 和事件监听器。
- 限制设备像素比并按视口缩放渲染分辨率；性能下降时先降低景深层、Bloom 和粒子密度，保留歌词清晰度。具体质量档位在实施计划中结合设备测试确定。
- WebGL 初始化失败或上下文丢失时不可黑屏：回退为精简 Canvas 歌词舞台并显示简短降级提示；恢复上下文后再切回 WebGL。降级路径不算 WebGL 视觉验收通过。
- 不引入 Folia 的资源文件、源码片段或运行时；新的光场、构图、转场和字形动画在 MIMI 中独立实现。

## 8. 验收标准

1. 对照用户提供的当前截图，固定灯架、地面透视网格和中心卡拉 OK 双行排布全部消失；静态截图能看出歌词与场景共同构图。
2. 1920×1080 宽屏下，画面有连续环境色场、可见景深、局部光束、主题线稿/图形、少量微尘和具有阅读优先级的主歌词；不是纯黑背景加稀疏点星。
3. 同一效果中至少观察到云阶式错落、浮名式大字深度和绘光式字面受光三种构图机制；统一色彩/材质，不出现三套互斥主题切换。
4. 同一首歌的同一音乐时刻在重绘、暂停、倍速、seek 前后得到同一镜头、字形进度和光位；多行同刻歌词独立排版。
5. LRC 估算单位完整覆盖其行时间段，视觉扫光连续，快歌词不残留孤立的随机单字高亮；无歌词/间奏没有伪造歌词。
6. 窄屏和极端宽高比不裁掉主歌词；暂停、恢复、seek、切歌、页面隐藏和 WebGL 上下文恢复均正确。
7. 全屏静止后只留下 MV 画面；活动后恢复主播放控件，重复小播放器、AI 语录与装饰角色不与歌词争位。
8. 在真实可播放会话中核验动态歌词、暂停、seek、倍速和切歌，并由用户复核视觉结果。测试、类型检查、构建及实际播放证据分别记录；静态验证不能替代实际播放和视觉验收。

## 9. 本规格不包含

- 不把 Folia 所有歌词模式复制成新的切换器；只为「温光浮字」吸收云阶、浮名、绘光的构图和渲染机制。
- 不改变歌词服务或歌曲存储格式，不声称 LRC 能产生真实逐词同步。
- 不迁移其他可视化，不改 Home/Player 页面和全屏歌词核心，不加入背景视频下载或远程素材。
- 不宣称逐像素复制 Folia；验收的是可识别的 MV 导演感、歌词空间和光效层级，并确保实现独立。
