# MIMI Music Player 标志设计方案

- 日期：2026-09-30
- 状态：候选方案评审中
- 分支：`feature/brand-logo-concepts`
- 范围：制作三种可比较的图形标志候选，不替换当前线上/应用内标志

## 1. 背景

项目品牌定位是高端、沉浸式、以音乐可视化为特色的播放器。现有颜色系统以深碳色背景为基底，使用紫、粉、青等高饱和信号色。当前图形标志是戴耳机的双猫插画：浏览器图标来自 `public/logo.svg`，工具栏则使用 `src/components/layout/Logo.tsx` 中另一份内嵌 SVG。工具栏徽标按 22px 使用，浏览器图标可能缩至 16px。

当前插画亲和、细节丰富，但缩小时五官、耳机、阴影和装饰难以辨认，与产品高端、精确、偏抽象的视觉定位不完全一致。设计探索需要同时保留猫咪记忆点与音乐属性，并优先解决 16–22px 的识别度。

## 2. 已确认的设计约束

| 项目     | 决策                                                                          |
| -------- | ----------------------------------------------------------------------------- |
| 品牌符号 | 猫咪与音乐信号融合，避免写实或复杂表情                                        |
| 主体构形 | 让猫耳与字母 M 的轮廓相结合                                                   |
| 品牌文字 | 图形标志本身不放文字                                                          |
| 配色     | 白色主体加一个霓虹强调色；本轮统一用现有 Aurora Purple 紫色，以便公平比较构形 |
| 首要尺寸 | 工具栏 22px、浏览器图标 16px                                                  |
| 主稿背景 | 透明                                                                          |
| 浅色背景 | 另备深色单色图形                                                              |
| 启动图标 | 深碳色圆角底板搭配白色主体与紫色强调色                                        |
| 动效     | 不在图形内部增加动画；如果最终接入现有 `Logo` 组件，保留轻微悬停/按压缩放行为 |

紫色取自 `DESIGN.md` 的 Aurora Primary token（`oklch(60% 0.25 300)`）。本轮将构形作为主要比较变量，避免同时比较粉色、青色或多色渐变造成判断偏差。若用户评审后希望改用粉色，三版统一换色再比较。

## 3. 三种候选构形

三种方案共用相同画布比例、颜色、透明背景和尺寸验收条件。每一种都应提供白/紫透明底主稿、深色单色版和启动图标预览。

### 方案 A：M 波形猫耳

- 两个向上的尖峰暗示猫耳，整体外轮廓读作几何化的 M。
- M 的下沿或一侧以一个短促的节拍转折收笔，表达音乐信号。
- 紫色只用于一个清楚的小信号节点；主体使用白色实形，不依赖细线、阴影或渐变。
- 优点：最贴合已确认的 M 与猫耳方向，轮廓简洁，最有机会在 16px 下保持识别。
- 风险：如果声波转折过于突出，会削弱 M 的阅读；如果猫耳太尖，可能偏向通用科技符号。

### 方案 B：声纹猫脸

- 用两侧猫耳和简化脸部轮廓形成猫的第一印象。
- 将一段声纹/节拍融入脸部的留白或下半部，不画眼睛、胡须等微小五官。
- 紫色用于声纹中的一个短节拍，白色承担主要轮廓。
- 优点：猫咪辨识度最强，延续现有吉祥物记忆。
- 风险：图形容易被读成角色头像；若声纹和轮廓同时出现，16–22px 下容易拥挤。

### 方案 C：猫尾旋律线

- 以一条连续、较粗的曲线构成简化 M/旋律轨迹，末端回勾成猫尾。
- 将曲线转折视作节拍变化；用紫色标出一个端点或节拍节点。
- 避免依赖细描边，曲线需在小尺寸栅格化后仍连贯。
- 优点：最轻盈、有动势，适合表现音乐流动。
- 风险：猫的特征最含蓄，曲线也最容易在 16px 下变细、变形。

## 4. 视觉与技术交付

原型阶段建议将候选放在独立目录，不触碰生产标志：

- `docs/nbl/specs/assets/mimi-logo-concepts/option-a.svg`
- `docs/nbl/specs/assets/mimi-logo-concepts/option-b.svg`
- `docs/nbl/specs/assets/mimi-logo-concepts/option-c.svg`
- `docs/nbl/specs/assets/mimi-logo-concepts/comparison.svg`

候选 SVG 使用透明底、固定 `viewBox`、显式填充色和简洁矢量路径，不嵌入位图、字体、滤镜、模糊或发光效果。比较页需在深碳色和浅色样板上分别呈现，并同时展示 64px、22px、16px 视图，以及深色单色版和圆角启动图标预览。比较页只用于设计评审，不作为应用入口或生产资源。

若候选获选并进入集成阶段，再更新 `public/logo.svg` 与 `src/components/layout/Logo.tsx` 的重复图形，确保浏览器图标和界面徽标一致；浅色单色版作为独立资源保留，启动图标另带深碳色底板。集成时需检查徽标的无障碍名称由外层链接/按钮提供，纯装饰实例不重复朗读图形名称。

## 5. 小尺寸与背景边界

- 16px favicon：保留主轮廓和一个可辨认的强调节点；删除内部细节。若紫色节点影响轮廓识别，应在该尺寸退化为单色版本。
- 22px 工具栏：不出现小于约 1.5px 的关键线段，不依赖透明阴影或渐变维持轮廓。
- 64px 及以上：保持与小尺寸相同的核心几何，不额外添加装饰细节。
- 深色界面：使用白色主体与紫色节点的透明底主稿。
- 浅色界面：使用深碳色单色稿，避免白色图形消失。
- 桌面/启动图标：将同一主符号置于深碳色圆角底板，不把底板烘焙进透明底主稿。

## 6. 不在本轮范围内

- 现在替换应用中的生产 Logo、favicon 或其他品牌资源。
- 修改 V7 Home View、Player View、全屏歌词或工具栏布局。
- 改变 `Logo` 组件的悬停/按压行为。
- 引入新依赖、字体、图像生成运行库或数据格式。
- 在未比较候选前决定最终方向或提交品牌文字锁定版。

## 7. 评审与验收

用户需要能直接比较三种候选，而不需要阅读 SVG 源码。比较页应回答：

1. 每个构形在 64px、22px、16px 下是否仍可辨认？
2. M、猫咪、音乐信号三种暗示是否平衡？
3. 白/紫主稿在深色背景上是否清楚，深色单色版在浅色背景上是否清楚？
4. 三种方案是否共用一致的颜色、比例和展示条件？
5. 设计原型是否与现有生产 Logo 完全隔离？

原型验收以实际查看比较页为准：三种候选均需在目标尺寸和两种背景上保持清楚；比较页应完整包含主稿、深色单色版与启动图标预览；生产 Logo 文件保持原样。最终采用哪一版由用户看过三种候选后决定。

## 8. 实施顺序

1. 用户评审本方案，确认范围与三种构形描述。
2. 依据获批方案制作三份候选 SVG 和比较页，做 16/22/64px 视觉检查。
3. 用户比较候选并指定最终方向；如需修改，三版保持同一颜色和展示标准后再迭代。
4. 最终方向确认后，单独确定是否将选中方案集成到生产 Logo 与 favicon。
